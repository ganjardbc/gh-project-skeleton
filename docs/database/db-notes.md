# Database Notes

## Engine

MySQL 8, accessed through Prisma 7 with the MariaDB driver adapter. Connection setup is in [database-config.md](database-config.md).

## Conventions

- **DB-first.** Prisma model and field names match the MySQL tables and columns: snake_case, plural table names.
- **IDs.** UUID stored as `CHAR(36)`, generated by the database (`DEFAULT (uuid())`).
- **Timestamps.** `created_at` and `updated_at` on every table.

## Tables

| Table | Purpose | Notes |
|---|---|---|
| `merchants` | Tenant | `slug` globally unique; `logo_upload_id` → `uploads` |
| `users` | Accounts | Belongs to one merchant; `avatar_upload_id` → `uploads`; `is_active` for soft delete |
| `roles` | RBAC roles | Global; `name` unique |
| `permissions` | RBAC permission codes | Global; `code` unique |
| `role_permissions` | Role ↔ permission | Composite key `(role_id, permission_id)` |
| `user_roles` | User ↔ role | Composite key `(user_id, role_id)` |
| `uploads` | File metadata | Storage key, bucket, MIME type, size, uploader |
| `notifications` | Per-user notifications | `type`, `is_read` |

## Uniqueness

- `merchants.slug`
- `users (merchant_id, email)` and `users (merchant_id, username)`: unique per merchant, not globally
- `roles.name`, `permissions.code`

## Indexes

Index foreign keys and columns that are filtered often. Existing indexes:

- `users.merchant_id`, `users.avatar_upload_id`
- `merchants.logo_upload_id`
- `user_roles.user_id`, `user_roles.role_id`, `role_permissions.permission_id`
- `uploads.uploaded_by_id`
- `notifications.user_id`, `notifications.is_read`, `notifications.created_at`

A new tenant-owned table needs an index on `merchant_id`.

## Delete behavior

| Parent deleted | Effect |
|---|---|
| Merchant | Its users are deleted |
| User | Its `user_roles` and `notifications` are deleted |
| Role or permission | Its link rows are deleted |
| Upload | `logo_upload_id` / `avatar_upload_id` referencing it are set to `NULL` |

Users are normally soft-deleted by the API (`is_active = false`), so these cascades apply only to a hard delete.

## Audit fields

`created_by` and `updated_by` exist on `merchants`, `users`, `permissions`, `role_permissions`, and `user_roles`. `roles`, `uploads`, and `notifications` do not have them. Values come from the authenticated user, never from the client.

## Migrations and seed

```bash
pnpm db:migrate    # prisma migrate dev
pnpm db:seed       # roles, permissions, demo merchant and users
pnpm db:generate   # regenerate the Prisma client
pnpm db:studio     # browse data
```
