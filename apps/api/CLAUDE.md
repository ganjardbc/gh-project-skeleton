## Project Overview

GH Skeleton API is a multi-tenant SaaS backend skeleton: auth, merchants, users, flat RBAC, uploads, notifications, and settings. Built with NestJS 11, Prisma 7 (MariaDB driver adapter), and MySQL.

## Architecture

**Modular monolith** with clear layer boundaries:

```
src/
├── auth/           # Login, register, profile; JWT strategy
├── merchants/      # Merchant (tenant) CRUD + logo
├── users/          # User CRUD + avatar, merchant-scoped
├── rbac/           # Roles, permissions, role↔permission, user↔role
├── settings/       # Profile, password, email, account, site settings
├── uploads/        # File uploads; local and S3 storage drivers
├── notifications/  # Per-user notifications
├── database/       # PrismaService (global)
├── common/         # Decorators, guards, pipes, interceptors, filters, DTOs
├── app.module.ts
└── main.ts
prisma/
├── schema.prisma   # 8 models: merchants, users, roles, permissions,
│                   #   role_permissions, user_roles, uploads, notifications
├── migrations/
└── seed.ts
```

Each module follows `dto/`, `<name>.module.ts`, `<name>.controller.ts`, `<name>.service.ts`. Register new modules in `app.module.ts`.

### Layer Rules

- **Controller**: DTO input, decorators, service call, response. No DB queries, no business logic.
- **Service**: Business logic, Prisma access, transactions, tenant scoping.
- **Prisma**: Only inside services, always through the injected `PrismaService` — never `new PrismaClient()`.

### Request Pipeline (`main.ts`)

- Global prefix `api/v1`; Swagger UI at `/docs`.
- `/uploads/local` serves the local `uploads/` directory as static files.
- Global `ValidationPipe`, `HttpExceptionFilter`, `TransformInterceptor`.
- `JwtAuthGuard` is registered globally as `APP_GUARD`: every route is protected unless marked `@Public()`.
- `PermissionGuard` is **not** global. Add `@UseGuards(PermissionGuard)` on the controller, then `@RequirePermission('resource.action')` per handler. A handler without `@RequirePermission` only requires a valid JWT.

### Authenticated User

`JwtStrategy.validate()` loads the user on every request and sets `request.user` to:

```ts
{ id, email, name, merchant_id, merchant: { id, name, slug }, is_active }
```

Read it with `@CurrentUser()` or a single field with `@CurrentUser('merchant_id')`.

### Multi-Tenant Enforcement

- `merchant_id` comes from `@CurrentUser('merchant_id')` — never from the request body, query, or params.
- All tenant-owned queries must filter by `merchant_id`.
- `users.email` and `users.username` are unique per merchant (`@@unique([merchant_id, email])`), not globally.
- `roles` and `permissions` are global tables with no `merchant_id`.

## Domain Rules

- **RBAC**: Flat. `user_roles` is `(user_id, role_id)`; effective permissions are the union across all of a user's roles. Access is granted by permission code, never by role name.
- **Registration**: Creates the merchant and the user in one transaction and assigns the `owner` role, which must already exist (run the seed).
- **Users**: Deleting a user is a soft delete (`is_active = false`). Inactive users cannot log in or pass the JWT guard.
- **Uploads**: Stored through a driver chosen by `STORAGE_DRIVER` (`local` or `s3`). Merchant logos and user avatars reference `uploads.id`; read URLs are resolved as signed URLs.
- **Audit columns**: Set `created_by` / `updated_by` from the current user where the table has them.

## Database Conventions

- DB-first: Prisma model and field names match the MySQL tables and columns (snake_case).
- UUID `CHAR(36)` primary keys, generated by the database.
- Index foreign keys and frequently filtered columns.
- See `docs/database/database-design.md` and `docs/backend/prisma-guidelines.md`.

## Common Module

| Component | Purpose |
|-----------|---------|
| `@CurrentUser()` | Get the authenticated user, or one field of it |
| `@RequirePermission()` | Require a permission code (needs `PermissionGuard`) |
| `@Public()` | Skip JWT auth for an endpoint |
| `JwtAuthGuard` | Global JWT protection |
| `PermissionGuard` | Permission check against the database |
| `TransformInterceptor` | Wrap responses in `{ success, data }` |
| `ValidationPipe` | DTO validation + transform |
| `HttpExceptionFilter` | Standardize error responses |
| `PaginationDto` | `page` / `limit` query params, `skip`, `calculateMeta()` |
| `ExcelExportService` | XLSX export helper |

## API Conventions

**Success**:
```json
{ "success": true, "data": {} }
```

**Error**:
```json
{ "success": false, "message": "...", "code": "..." }
```

**Pagination**: accept `PaginationDto` via `@Query()` and return `{ data, meta }` from the service, where meta is `{ total, page, limit, totalPages }` (matches `PaginationMeta` in `@gh-skeleton/shared-types`). `TransformInterceptor` wraps it, so the wire shape is `{ "success": true, "data": { "data": [], "meta": {} } }`.

**Permission codes**: `<resource>.<action>`, e.g. `user.create`, `merchants.read`, `role.assign`, `upload.delete`. The seeded list is in `prisma/seed.ts`.

## Gotchas

- A permission code used in `@RequirePermission` must exist in the `permissions` table and be attached to a role. The `settings.*` codes used by `SettingsController` are not in `prisma/seed.ts`.
- `PORT` defaults to 3030 when unset.
- `postinstall` runs `prisma generate`, so the client is rebuilt after every `pnpm install`. It is allowed to fail (the Docker build installs before the schema is copied and generates explicitly afterwards). If services report `Property 'users' does not exist on type 'PrismaService'`, run `pnpm db:generate`.
- `src/nama-modul-test/` is an empty leftover scaffold, not a real module.

## Environment

Required `.env` variables (full list in `.env.example`):
- `DATABASE_URL` — MySQL connection string
- `JWT_SECRET` — secret for JWT tokens; always set it, the code has an insecure development fallback
- `JWT_EXPIRES_IN` — present in `.env.example` but not read; the token lifetime is fixed at `7d` in `src/auth/auth.module.ts`
- `PORT` — server port
- `CORS_ORIGIN` — comma-separated allowed origins
- `STORAGE_DRIVER` — `local` or `s3`; S3 also needs `AWS_REGION`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `S3_BUCKET_NAME`
- Upload limits: `MAX_FILE_SIZE`, `ALLOWED_MIME_TYPES`, `SIGNED_URL_EXPIRY`
